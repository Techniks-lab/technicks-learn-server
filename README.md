## Description

[Nest](https://github.com/nestjs/nest) framework TypeScript starter repository.

## Project setup

```bash
$ yarn install
```

## Compile and run the project

```bash
# development
$ yarn run start

# watch mode
$ yarn run start:dev

# production mode
$ yarn run start:prod
```

## Run tests

```bash
# unit tests
$ yarn run test

# e2e tests
$ yarn run test:e2e

# test coverage
$ yarn run test:cov
```

## Deployment (Render)

This is a standard long-running Node web service — Render runs it without code changes.

1. Push the repo to GitHub.
2. Render: **New → Blueprint** and pick this repo (uses `render.yaml`), or create a **Web Service** and set:
   - Runtime: **Node 22**
   - Build command: `npm ci && npm run build`
   - Start command: `npm run start:prod`
   - Health check path: `/api/v1/health` (already implemented — pings the database)
3. Set the environment variables: `DATABASE_URL`, `JWT_SECRET`, `JWT_EXPIRES_IN`, `REFRESH_TOKEN_EXPIRES_IN`, `BREVO_API_KEY`, `BREVO_SENDER_EMAIL`, `BREVO_SENDER_NAME`, `CORS_ORIGIN`.
4. **Apply database migrations before the first deploy** (from your machine or CI), never from Render:

   ```bash
   npx prisma db migrate
   ```

5. Point the client at the live API with `EXPO_PUBLIC_API_URL=https://<your-app>.onrender.com/api/v1` (SDK generation scripts can also target `https://<your-app>.onrender.com/docs/<Tag>.json`).

> Free tier web services spin down after ~15 min of inactivity — the first request wakes the instance. Use a paid/`always on` instance or an uptime keep-alive (e.g. UptimeRobot) to keep it warm.
